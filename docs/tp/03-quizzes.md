# TP 3 — Quizzes

Do the exercises before you read the correction. Stay in your practice folder.

In **this** practical, `category` is a string stored on the quiz, such as `"Programming"`. Practical 4 replaces that string with the id of a category document. The checks below (who may write, how a question is shaped) stay the same after that change.

## Goal

One quiz is one MongoDB document. Its questions live **inside** that document. Anyone can list and open a quiz. Only a logged-in user can create one, and only the author can update or delete it.

## What you already have

Practical 2: `users`, signup, login, and `requireAuth`, which sets `res.locals.userId`.

## Ideas you need

**Embed the questions.** A quiz is always loaded with its questions. A separate `questions` collection would mean a second query and a second id to keep in sync. The document looks like this:

```text
{
  title: "Loops",
  category: "Programming",
  questions: [
    { text: "What does i++ do?", options: ["adds 1", "stops", "prints", "waits"], correct: 0 }
  ],
  author: ObjectId("...")
}
```

Each question still has its own `_id`, because the play screen needs an id per question. That id is generated by mongoose. The client does not send it.

**The author comes from the token.** `requireAuth` already stored the user id on `res.locals.userId`. You copy that into `author` when you create the quiz. If you trusted `author` from the JSON body, anyone could pretend to be someone else.

**Who can do what**

| Request | Who | Success | If something is wrong |
|---|---|---|---|
| `GET /api/quizzes` | anyone | `200` and `{ quizzes }` | |
| `GET /api/quizzes/:id` | anyone | `200` and `{ quiz }` | unknown id → `404` `Quiz not found.` |
| `POST /api/quizzes` | logged in | `201` and `{ quiz }` | no token → `401` `Please log in.` Bad body → `400` and the first Zod message |
| `PATCH /api/quizzes/:id` | the author | `200` and `{ quiz }` | not the author → `403` `You can only edit your own quizzes.` |
| `DELETE /api/quizzes/:id` | the author | `204` and an empty body | not the author → `403` `You can only delete your own quizzes.` |

`204` means "done, and there is no JSON". Your client must not call `response.json()` on it.

An id that is not a MongoDB id, such as `abc`, is the same as a missing quiz: `404` and `Quiz not found.`

`GET /api/quizzes?category=Programming` returns only quizzes whose `category` string is `Programming`, newest first. No query returns every quiz, newest first.

## Exercise 1 — The quiz model

Create `src/models/Quiz.ts`.

A question has `text`, `options` (an array of strings), and `correct` (a number). Give the question schema `{ _id: true }`.

A quiz has `title`, `category` (string, trimmed, required), `questions` (required array), and `author` (ObjectId, ref `"User"`, required). Turn timestamps on. Index `{ category: 1, createdAt: -1 }` so the list for one type is cheap.

`toPublicQuiz` returns:

```text
id, title, category, questions, authorId, createdAt
```

Each question in that answer has `id` (the question `_id` as a string), `text`, `options`, `correct`. `authorId` is `author` as a string. `createdAt` is an ISO string. Do not send `passwordHash`, and do not send mongoose's `__v`.

**Check.** This becomes visible in exercise 3. In Compass, after you create a quiz, `questions[0]._id` exists even though the request did not send an id.

## Exercise 2 — Check the body

In `src/routes/quizzes.ts`, describe a valid quiz with Zod:

- `title`: trimmed, 1 to 80 characters. Empty: `Please enter a quiz title.` Too long: `Quiz title must be 80 characters or fewer.`
- `category`: trimmed, 1 to 40 characters. Empty: `Please choose a type.` Too long: `Type name must be 40 characters or fewer.`
- `questions`: at least one. Otherwise: `Add at least one question.`
- Each question: `text` non-empty (`Please enter your question.`), `options` a tuple of **four** non-empty strings (`Fill in all four answer options.`), `correct` an integer from 0 to 3 (`Select the correct answer.`).

On failure, answer `400` with `{ message }` set to the **first** issue only.

Mount the router **before** the error handler:

```ts
app.use("/api/quizzes", quizRouter);
```

## Exercise 3 — Create, list, and get

`POST /` uses `requireAuth`. Build the document from the parsed title, category, and questions. Set `author` to `res.locals.userId`. Answer `201`.

`GET /` reads `req.query.category`. If it is a non-empty string, filter with `{ category: that string }` after `trim`. Sort `{ createdAt: -1 }`. Answer `{ quizzes: [...] }` using `toPublicQuiz`.

`GET /:id` loads one quiz. Invalid or unknown id → `404` and `Quiz not found.`

Register `GET /` before `GET /:id`. Express matches in order. A path parameter would otherwise treat the word `categories` as an id. You are not adding `/categories` in this practical, and the order still matters for later.

**Check.** Sign up or log in (practical 2) and keep the token.

```js
const token = "paste-the-token";
const quiz = {
  title: "Loops",
  category: "Programming",
  questions: [
    { text: "What does i++ do?", options: ["adds 1", "stops", "prints", "waits"], correct: 0 },
  ],
};

const created = await fetch("http://localhost:4000/api/quizzes", {
  method: "POST",
  headers: { "Content-Type": "application/json", Authorization: `Bearer ${token}` },
  body: JSON.stringify(quiz),
});
console.log(created.status, await created.text());
```

- No `Authorization` header → `401` `Please log in.`
- `options` with three strings → `400` `Fill in all four answer options.`
- The body above → `201`. `authorId` equals the id inside your token (`sub`), not a field you sent.
- `GET /api/quizzes?category=Programming` → `200`, and the new quiz is in the list.
- `GET /api/quizzes?category=Math` → `200` and `quizzes` is `[]` if you have no math quiz.
- `GET /api/quizzes/not-an-id` → `404` `Quiz not found.`

## Exercise 4 — Update and delete, author only

`PATCH /:id` and `DELETE /:id` both use `requireAuth`.

1. Load the quiz. Missing → `404` `Quiz not found.`
2. If `quiz.author.toString()` is not `res.locals.userId` → `403` with `You can only edit your own quizzes.` or `You can only delete your own quizzes.`
3. PATCH checks the body with the same schema as POST, assigns `title`, `category`, and `questions`, saves, and answers `200`.
4. DELETE calls `deleteOne()` and answers `204` with no body.

Create a second user and try to delete the first user's quiz with the second token.

**Check.**

- Second user `DELETE` → `403` `You can only delete your own quizzes.` The quiz is still there.
- Author `PATCH` with a new title → `200` and the new title. `authorId` is unchanged.
- Author `DELETE` → `204`. The next `GET` of that id → `404`.

## What you can skip

Do not create a `categories` collection yet. Do not add `builtIn`. A category here is only the string on the quiz. Two quizzes can both say `"History"` without a History document existing.

# Correction

Owner checks and validation in the repo match this practical. The **stored** category does not: [backend/src/models/Quiz.ts](../../backend/src/models/Quiz.ts) and [backend/src/routes/quizzes.ts](../../backend/src/routes/quizzes.ts) store a category **id**, because practical 4 changes that. When you compare, look at `requireAuth`, the Zod messages, `author: res.locals.userId`, and the `403` strings. Those are the point of this practical.

For this practical, the schema field is a string:

```ts
category: { type: String, required: true, trim: true },
author: { type: Schema.Types.ObjectId, ref: "User", required: true },
questions: { type: [questionSchema], required: true },
```

`toPublicQuiz` copies that string straight into the answer. In the repo, the same function reads `category.name` after the category document has been loaded. You will change that in practical 4. Until then:

```ts
category: plain.category,
authorId: plain.author.toString(),
createdAt: plain.createdAt.toISOString(),
```

Question ids come from mongoose. Cast each stored question so TypeScript knows `_id` exists, then call `toString()`:

```ts
questions: plain.questions.map((question) => {
  const stored = question as IQuestion & { _id: mongoose.Types.ObjectId };
  return {
    id: stored._id.toString(),
    text: stored.text,
    options: stored.options,
    correct: stored.correct,
  };
}),
```

Create ignores any author in the body. The object you pass to `Quiz.create` sets `author` yourself:

```ts
const quiz = await Quiz.create({
  title: parsed.data.title,
  category: parsed.data.category,
  questions: parsed.data.questions,
  author: res.locals.userId,
});
res.status(201).json({ quiz: toPublicQuiz(quiz) });
```

The list filter is a string compare. Practical 4 replaces this with "find the category by name, then find quizzes with that id".

```ts
const category = typeof req.query.category === "string" ? req.query.category.trim() : "";
const quizzes = await Quiz.find(category ? { category } : {}).sort({ createdAt: -1 });
res.json({ quizzes: quizzes.map(toPublicQuiz) });
```

Delete is the pattern you will reuse for categories: missing, then not the owner, then the action.

```ts
if (!quiz) {
  res.status(404).json({ message: "Quiz not found." });
  return;
}
if (quiz.author.toString() !== res.locals.userId) {
  res.status(403).json({ message: "You can only delete your own quizzes." });
  return;
}
await quiz.deleteOne();
res.status(204).send();
```

`findQuiz` should return `null` when `mongoose.isValidObjectId(id)` is false. `Quiz.findById("not-an-id")` throws a cast error, and the person would see `500` instead of `404`.

Next practical: a category becomes its own document, and the quiz stores that document's id.
